# Docs

A single-user document editor: a document list, a
page-style rich-text editor with autosave, version history and export to Word,
Markdown and PDF.

The design follows how the reference product saves edits (see
[docs/research.md](docs/research.md)), so real-time collaboration can be added
later without changing the storage model.

## Requirements

- Node.js 24 or later
- Chrome, for the end-to-end tests only

## Run it

```bash
npm install
npm run dev
```

Open <http://localhost:5173>. The API server runs on port 3001, and Vite proxies
`/api` and `/uploads` to it.

Documents and uploaded images are stored in `data/` (`docs.sqlite` and
`uploads/`). Set `DATA_DIR` to store them elsewhere.

For a production build served from one port:

```bash
npm run build
npm start          # http://localhost:3001
```

## Backups

```bash
npm run backup
```

This writes `backups/<timestamp>/` with a copy of the database (`docs.sqlite`) and
the `uploads/` directory, and deletes all but the 20 newest backups. The database
is copied with SQLite's `VACUUM INTO`, which reads one consistent snapshot, so it
is safe to run while the server is running. `DATA_DIR` and `BACKUP_DIR` override
the `data/` and `backups/` directories.

To restore a backup:

1. Stop the server.
2. Move the current `data/` directory aside, for example to `data.old/`.
3. Copy the backup into place:
   `cp -R backups/<timestamp> data` (a fresh `data/` with `docs.sqlite` and
   `uploads/`). Do not copy `docs.sqlite-wal` or `docs.sqlite-shm` files from the
   old directory: they belong to the old database.
4. Start the server and check your documents, then delete `data.old/`.

## Features

- **Document list:** a grid of page thumbnails or a list grouped by date
  (Today, Previous 7 days, Previous 30 days, Earlier); search titles and
  contents; sort by last opened, last modified or title; rename, remove or open
  in a new tab from each document's ⋮ menu. The view, sort and owner filter are
  remembered in the browser. Thumbnails are drawn from the top of each
  document's first page when its tile scrolls into view.
- **Templates:** a blank document or one of four built-in templates (Letter,
  Resume, Project proposal, Report, in `shared/src/templates.ts`).
- **Import:** Open file picker opens Word (.docx) and Markdown (.md) files up to
  20 MB as new documents (see [How import works](#how-import-works)).
- **Editor:** paragraph styles (Normal text, Title, Subtitle, Heading 1–6,
  ⌘⌥0–6), fonts and font sizes, bold, italic, underline, strikethrough (⌘⇧X),
  superscript (⌘.), subscript (⌘,), capitalisation (lowercase, UPPERCASE,
  Title Case), text and highlight colour, paint format, links, images (upload,
  by URL, paste or drag and drop), tables (see below), bulleted
  and numbered lists with glyph and numbering presets, checklists (⌘⇧9),
  alignment, line spacing, space before and after paragraphs (Custom spacing),
  indentation (⌘] and ⌘[ move to the next half inch; the ruler sets any left,
  first line or hanging and right indent), tab characters (Tab, outside lists
  and tables) and tab stops, page breaks
  (⌘↵), quotes, code blocks, horizontal lines, undo and redo, zoom (presets,
  typed or Fit).
- **Special characters** (Insert > Symbols > Special characters, or Emoji): a
  dialog that stays open near the bottom of the editor area. Pick a category
  (Symbol, Punctuation, Emoji, Number, Latin) and subcategory, hover a
  character for its code point and name, click to insert it at the cursor, or
  search by keyword ("arrow") or code point ("U+2192" or "2192"). The
  characters and their Unicode names are generated by
  `scripts/build-characters.mjs` from the pinned `@unicode/unicode-16.0.0`
  package and loaded only when the dialog first opens. There is no
  handwriting area.
- **Tables:** Insert > Table picks the size in a grid that grows from 5 × 5 to
  20 × 20. Tables fill the width between the margins with equal columns; drag
  the border between two columns to change their widths (stored in the
  document as each cell's `colwidth` and shown as proportions, so a table still
  fills the page after the margins change). Format > Table and the right-click
  menu insert and delete rows and columns, distribute rows and columns, merge
  and unmerge cells, and sort the rows by the cursor's column (header rows stay
  on top; one undo step). Table options (a side panel) shows the number of
  columns and rows and sets the minimum row height, border colour and width,
  and cell background colour.
- **Images:** click an image to select it: an outline with eight handles (and a
  rotation handle, not available yet). Corner handles resize keeping the
  proportions, edge handles stretch one side (Shift keeps the proportions);
  the size is stored as the image's `width` and `height`. A pill under the
  image has Wrap text options (in line with text only), Image options (size and
  alt text) and Add comment; while it is selected the toolbar shows the image
  controls (border and crop, not available yet). Delete or Backspace removes it.
- **Right-click menu:** the document has its own menu (Shift+right-click shows
  the browser's, for spelling suggestions) with the clipboard commands,
  Comment, Insert or Edit link (plus Copy link and Remove link on a link),
  Format options and Clear formatting, and the table commands inside a table.
  A right-click inside the selection keeps it; elsewhere it moves the cursor
  to the pointer first.
- **Menus and toolbar:** a File / Edit / View / Insert / Format / Tools menu
  bar with submenus and keyboard navigation, and a toolbar whose controls move
  into a "More" row when the window is narrow. Both follow the WAI-ARIA menubar
  and toolbar patterns: each is one Tab stop, ← → move within it, and Escape
  returns to the document. Alt+F10 moves from the document to the toolbar. Menu items for features that
  are not built yet are shown disabled; they call the optional actions listed
  in `client/src/editor/actions.ts`.
- **Pages:** the document is shown as separate pages of its paper size with a
  10px gap between them; text that does not fit continues on the next page,
  line by line. File > Page setup has a Pages tab with orientation, paper size
  (A4, Letter, Legal, A5, A3), page colour and margins per document, and "Set
  as default" to start new documents (blank or from a template) with those
  settings (kept in the browser); its Pageless tab switches to one continuous
  sheet. New documents otherwise use Letter in the United States and A4
  elsewhere. A horizontal and a vertical ruler (in centimetres, or inches in the
  United States) show the margins and the current paragraph's indents. Drag the
  left indent (the first line moves with it), first line and right indent
  markers to indent the selected paragraphs, or the shaded margin areas to
  change the left and right margins; a dotted line and the value show while
  dragging, values snap to 0.25 cm (⅛ in) and Alt turns snapping off. Click
  the ruler between the margins to add a left, centre or right tab stop there;
  drag a stop to move it (its position shows above the ruler) or off the ruler
  to remove it. Tabs advance to the next stop of their paragraph, or every
  1.27 cm from the left indent (see
  [docs/design/tab-stops.md](docs/design/tab-stops.md)). Markers can be
  grabbed up to 8px around their shape. The ruler
  indents the header, footer or footnote being edited, or else the body. View >
  Show ruler and View > Show print layout (off for one continuous sheet) are
  remembered in the browser.
- **Page elements** (Insert > Page elements, print layout only): headers and
  footers (also Ctrl+⌘O then Ctrl+⌘H or Ctrl+⌘F, or double-click the top or
  bottom margin) with their own formatting and alignment, "Different first
  page", and Options to add page numbers or remove them; page numbers (four
  presets, or More options for the position, the first page and the starting
  number) and a page count field; footnotes (⌘⌥F) at the bottom of their page,
  numbered in order; and a table of contents in three styles (page numbers,
  dotted leaders or blue links that jump to the heading), refreshed with the
  Update button on its pill. See [docs/design/page-elements.md](docs/design/page-elements.md).
- **Find** (⌘F): a card at the top right of the editor area highlights every
  match as you type, Enter and Shift+Enter move between them. **Find and
  replace** (⌘⇧H) adds match case, JavaScript regular expressions (`$1` in the
  replacement inserts a group) and ignoring diacritics (on by default, so
  "cafe" finds "café"); Replace all is one undo step. Text suggested for
  deletion is not searched.
- **Word count** (⌘⇧C) shows pages, words and characters for the document or
  the selection (text suggested for deletion is not counted), and can show a live count at the bottom left of the editor
  area.
- **Tabs and outline:** a sidebar (the list button at the top left, or View >
  Expand tabs and outlines sidebar) shows the document's tab with its number of
  open comments, and an outline of the Title and Heading 1–6 paragraphs, indented
  by level, with the heading at the cursor highlighted. Clicking a heading
  scrolls it to the top. Whether the sidebar is open is remembered.
- **Comments:** select text and choose Add comment on the floating pill, the
  toolbar, Insert > Comment or ⌘⌥M. Threads are cards in a margin right of the
  pages, level with their text and stacked 8px apart; the active card sits
  exactly beside its text. Reply, edit or delete messages and replies, resolve,
  copy a link that opens the document with the thread active (`?comment=<id>`),
  and delete threads. Comments stay attached to their text while you edit; if
  the text is deleted, the thread remains and shows the original text as
  deleted. View > Comments > Show all comments (⌘⌥⇧A, or the header button)
  lists all, open or resolved threads, where resolved ones can be reopened;
  Hide comments (⌘⌥⇧J) hides the margin and highlights and is remembered.
- **Suggesting mode** (the mode button at the right end of the toolbar, View >
  Mode, ⌘⌥⇧X to switch between Suggesting and Editing, ⌘⌥⇧Z for Editing and
  ⌘⌥⇧C for Viewing; remembered per document in the browser): typed text is
  shown in green, deleted text stays struck through in green, and formatting
  changes (text formatting, paragraph styles, alignment, spacing, indents and
  lists) are applied and shown in green. Consecutive edits at the same place
  are one suggestion until the cursor moves away or for 2 minutes. Each
  suggestion has a card in the comment margin ("Add", "Delete", "Replace",
  "Format") with Accept, Reject and replies; the active one is outlined in the
  document. Tools > Review suggested edits (Ctrl+⌘O then Ctrl+⌘U) steps through
  them, previews the document with all of them accepted or rejected, and
  accepts or rejects one or all (each one undo step). Viewing mode shows the
  document read-only as if every suggestion were accepted. Tables, images, page
  breaks, horizontal lines, the table of contents, headers, footers and
  footnotes are edited directly even in Suggesting mode. See
  [docs/design/suggesting.md](docs/design/suggesting.md).
- **Autosave:** edits are sent about 300 ms after you stop typing. The header
  shows whether changes are saving, saved, or waiting for the connection to come
  back. Edits the server has not confirmed are also kept in the browser
  (IndexedDB): after a lost connection, a closed tab or a crash they are sent
  the next time the document opens, rebased on newer changes and never applied
  twice. If that is impossible (the document was deleted), a dialog offers
  the unsaved text as a file.
- **Automatic formatting** (Tools > Preferences, kept in the browser):
  capitals at the start of sentences and for "i", smart quotes, links for
  typed addresses, lists from `1. `, `1) `, `a. `, `* ` and `- `, Markdown
  (`#`–`######` headings, `**bold**`, `*italic*`, `~~strikethrough~~`,
  `` `code` ``, `---`), and an editable list of substitutions (`(c)` ©, `-->`
  →, `1/2` ½…). ⌘Z right after an automatic change restores what was typed. In
  Suggesting mode the changes are suggestions too.
- **Link bubble:** with the cursor in a link, a card shows the page's title
  (fetched by the server), the address, and Copy, Edit and Remove.
- **Keyboard shortcuts** (⌘+/ or Tools > Keyboard shortcuts): every shortcut
  by group, with a search. Menus, tooltips, the editor and the dialog read them
  from one list (`client/src/shortcuts.ts`).
- **Paste:** HTML from web pages and word processors keeps its structure and
  basic formatting without Word's markup, classes or default fonts; pasted web
  and data images are copied into the uploads (a grey placeholder shows
  meanwhile). ⌘+Shift+V pastes plain text; a URL pasted on selected text links
  it. See [docs/design/everyday-editing.md](docs/design/everyday-editing.md).
- **Version history** (File > Version history > See version history, ⌘⌥⇧H or
  the clock button): edits are grouped into sessions separated by 5 minutes of
  inactivity. History mode replaces the header and toolbar with a top bar (Back,
  the selected version's time, Print, zoom) and lists the versions by day in a
  panel on the right, the newest marked "Current version". The selected version
  is shown as read-only pages. With Highlight changes (on by default), text it
  added compared with the version before it is marked in teal and text it
  removed is struck through in red; "Total: N edits" counts the changes and
  Previous edit / Next edit scroll between them. Each version's ⋮ menu can
  restore it (after a confirmation; the restore becomes a new version), name it,
  or make a copy as a new document. File > Version history > Name current
  version names the newest version, and the panel can show only named
  versions. Restoring replaces only the text that differs, so comments on
  unchanged text survive.
- **Export:** File > Download as Microsoft Word (.docx), plain text (.txt) or
  Markdown (.md). Word files use Word's Title, Subtitle and Heading 1–6 styles,
  the document's page size, orientation, margins and page colour, paragraph
  indents (left, first line or hanging, right), the tables' column
  widths, row heights, borders and cell colours, and the images' sizes; headers
  and footers (with a different first page), page number fields and the page
  number start, real Word footnotes, and the table of contents as paragraphs
  with right-aligned page numbers (and dotted leaders) or links to bookmarks on
  the headings. Suggestions become tracked changes (insertions, deletions,
  format changes and paragraph marks); Markdown and plain text are written as
  if every suggestion were accepted.
  In Markdown, Title becomes a level 1 heading, Subtitle a plain paragraph,
  checklists `- [ ]` / `- [x]`, superscript and subscript `<sup>` / `<sub>`,
  a page break the comment `<!-- page break -->`, footnotes `[^1]` with the
  notes at the end and a table of contents a list of links; headers and footers
  are left out. PDF uses the browser's print dialog: with print layout it prints
  the pages exactly as laid out on screen (headers, footers, footnotes and page
  numbers included), otherwise the browser breaks the pages with the
  document's margins. Edit > Copy as
  Markdown copies the selection.
- **Make a copy:** File > Make a copy creates "Copy of <title>" without the
  comments.

Keyboard shortcuts follow the reference product, for example ⌘K for links, ⌘⌥1–3 for
headings, ⌘⇧8 for bulleted lists and ⌘⌥⇧H for version history.

## How saving works

The editor (Tiptap, built on ProseMirror) records every change as a ProseMirror
step. `client/src/editor/sync.ts` sends unsaved steps in batches:

1. Changes are debounced into a batch; only one batch is in flight at a time.
2. Each batch carries the document version it was built on.
3. The server (`server/src/documents.ts`) applies the steps to its copy of the
   document, stores them and returns the new version.
4. If the batch is based on an old version, the server answers `409` with the
   steps the client is missing. `prosemirror-collab` rebases the local steps on
   top of them and the batch is sent again.
5. Network errors are retried with backoff. A rejected batch (invalid step)
   stops saving and asks the user to reload.
6. Before each batch is sent, the unconfirmed steps are written to IndexedDB with
   the version they are built on, so they survive a closed tab. A batch sent again
   after its answer was lost is recognised by the server (`alreadyApplied`), and
   when kept steps are restored, the server's steps from this session's client id
   show which of them it already has (see
   [docs/design/everyday-editing.md](docs/design/everyday-editing.md)).

The server validates every step against the same schema as the editor
(`shared/src/schema.ts`), so stored documents are always valid.

Comment anchors follow the same steps: the server moves every anchor through
each accepted batch (`server/src/comments.ts`), and the editor moves its copy
through every local change (`client/src/editor/commentAnchors.ts`). Both use the
same rule from `shared/src/anchors.ts`. A new comment is created only after
pending edits are saved, so its positions refer to the server's version.

To add real-time collaboration later, push accepted steps to other open
clients (for example over WebSocket) and apply them with `receiveTransaction`,
as the sync already does for conflicts.

## How pages work

Page settings are attributes of the document's top node (`shared/src/pageSetup.ts`),
changed with a ProseMirror `DocAttrStep`. They are saved, validated by the server,
undone and restored from version history like any other edit. Documents saved
before page settings existed open as A4 portrait with 2.54 cm margins and white
pages. The page colour (`pageColor`, `#rrggbb`) is drawn on each page sheet and,
when printing with print layout, behind the printed pages (pageless printing
leaves it out).

Paragraph indents are attributes of paragraphs and headings in points
(`indentLeft`, `indentFirstLine` relative to the left indent and negative for a
hanging indent, `indentRight`; `shared/src/indents.ts`). Documents saved before
them have `indent`, a number of half-inch steps, which still counts towards the
left indent, so they look the same; every change writes the whole left indent
to `indentLeft` and sets `indent` to 0. In a list, the indents add to the indent
of the list level.

On screen the editor is one content column over a stack of page sheets
(`client/src/editor/pagination.ts`). After each change the editor measures where
blocks and lines fall and inserts spacer widgets (decorations, not document
content) that push the next line past the bottom margin, the gap and the next
page's top margin. The rules are in `client/src/editor/pageLayout.ts`. Images,
tables and other atomic blocks move to the next page whole; one taller than a
page overflows.

Headers and footers are document attributes (block JSON) and footnote text is an
attribute of the footnote's reference, so they are saved, validated, undone and
versioned like the rest without moving any positions in the content. They are
edited in a second editor bound to that attribute, drawn over the pages by
`client/src/editor/PageElements.tsx`, and measured by the pagination: a tall
header or footer moves the content in, and footnotes take their space from the
bottom of the page their reference is on (a line whose footnotes do not fit
moves to the next page with them). Before printing, the pagination lays the
pages out again without gaps between them, and the `@page` rule uses the page's
size with no margins, so the printout matches the screen.

## How import works

The server converts the file into the shared schema (`server/src/import/`) and
checks the result against it before creating the document.

- **Word** (`docx.ts`, with JSZip and xml-js): Title, Subtitle and Heading 1–9
  styles (7–9 become Heading 6, outline levels count as headings), alignment,
  line spacing, space before and after, left, first line, hanging and right
  indents; bold, italic, underline,
  strikethrough, superscript, subscript, text colour, highlight, font size and
  font; links (hyperlinks and HYPERLINK fields); bulleted and numbered lists
  with the closest list preset, continued numbering and nesting; paragraphs
  starting with ☐ or ☑ (as the Word export writes checklists) become
  checklists; tables with merged cells, header rows and column widths; PNG, JPEG, GIF and WebP
  images (stored in `uploads/`); line and page breaks; page size, orientation,
  margins and page colour; the default and first-page header and footer, the page number
  start, PAGE and NUMPAGES fields and footnotes. Tracked changes in the body
  become suggestions (insertions, deletions, run format changes and inserted or
  deleted paragraph marks); in headers, footers and footnotes inserted text is
  kept and deleted text left out.
- **Markdown** (`markdown.ts`, with markdown-it): headings, emphasis,
  strikethrough, inline code, links, lists and `- [ ]` checklists, quotes, code
  blocks, horizontal lines, tables with column alignment, images (data URLs are
  stored, web addresses kept), `<u>`, `<sup>`, `<sub>`, `<mark>` and
  `<!-- page break -->`. A `#` heading becomes Heading 1, since Markdown cannot
  tell it apart from a Title.

Everything else is dropped, and the editor shows which kinds of content were
left out: endnotes, even-page headers and footers, comments, equations, text
boxes, charts and shapes, embedded objects, images in other formats or from
local paths, and other HTML.

## How the comment margin works

The pages and the comment margin sit side by side in one centred column
(`client/src/editor/CommentMargin.tsx`), so cards scroll with the text. After
every editor transaction, resize or zoom change the margin reads the top of each
anchor's line from the editor (`coordsAtPos`, which already includes page spacers
and zoom) and the height of each card, then `commentLayout.ts` stacks the cards in
document order: the active card stays at its line and the others move out of its
way with an 8px gap.

## How highlight changes works

`shared/src/versionDiff.ts` compares a version with the one before it (the oldest
with an empty document). It first matches equal top-level blocks (a longest common
subsequence), then compares the text of each run of changed blocks with
ProseMirror's changeset, which finds the changed characters and widens changes
inside a word to the whole word. Each resulting range is one edit. The preview
(`client/src/editor/HistoryMode.tsx`) is a read-only editor with the same
pagination as the editor; `versionHighlight.ts` marks added text and inserts the
removed text, struck through, where it was.

## Tests

```bash
npm test             # unit tests: step authority, revisions, comments, exports, imports, sync, search
npm run e2e          # browser tests against a throwaway server and data directory
npm run typecheck
npm run perf         # performance with a 60-page document, against the production build
```

`npm run perf` builds the client, opens a 60-page document with 40 comments, the
outline and the live word count, and prints the time to open it, the time until
the pages settle and frame times while typing on pages 1 and 50. Set
`PERF_CPU_THROTTLE=4` to emulate a slower computer and
`PERF_PROFILE=<file>.cpuprofile` to record a CPU profile of typing on page 50.
`PERF_MODE=suggesting` types in Suggesting mode.

## Limitations

- One user, no accounts or sharing.
- Tables are not split across pages, and printed page breaks can differ
  slightly from the screen because the browser paginates the printout.
- Images are always in line with text; wrapping, rotation, cropping and image
  borders are not available yet. Table alignment and fixed column widths in
  Table options are not available yet either.
- One section per document: no section breaks, so no different headers or
  page numbering per section; Header format (margins of the header and footer)
  is not available yet. Footnotes are paragraphs of text (no images or tables)
  and comments cannot be attached to header, footer or footnote text. Version
  history does not highlight changes in headers, footers or footnotes.
- Comments are not included in exports. The author is always "You"; emoji
  reactions and renaming the tab are not available yet.
- No real-time collaboration yet. Suggestions are always by "You"; the Preview
  reject all view still shows suggested formatting and paragraph breaks.
